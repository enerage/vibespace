# Decisions

Flat decision log — one line each, append-only, newest at the bottom. Format:
`- **<topic>** — <choice>. Why: <reason>. (YYYY-MM-DD)`

- **No caching in `app://`** — protocol reads disk + `Cache-Control: no-store`. Why: cached net.fetch served stale mixed bundles through hot reload. (2026-09-26)
- **Splitter drag physics** — frozen start size + cumulative clientX/Y deltas on window capture; no movementX, no pointer capture. Why: remote-control input and flexbox feedback spirals. (2026-09-26)
- **Dev hot reload is opt-in** (`--watch` / `VIBESPACE_WATCH=1`), default OFF. Why: every unpackaged process watched by default, so one save bounced every open workspace's agents. (2026-09-26)
- **Ptys survive renderer reloads** — main-side ring buffer (256 KB/term) + `pty:list` attach; logo swaps and renderer crashes recover without killing agents. Why: the running process IS the agent; transcripts are a fallback, not a refresh mechanism. (2026-09-26)
- **Agent status via injected hooks** — claude launches with `--settings` injecting hooks that append `working|waiting|done` to `$VIBESPACE_TERM_STATUS`; main watches → lights, toasts, badges. Why: reading the TUI is unreliable; we own the spawn. (2026-09-26)
- **⟳ and ↻ buttons are conditional** — only render when there's actually something to restart onto (claude disk≠baseline / source fingerprint changed). Why: always-on buttons train ignoring them. (2026-09-27)
- **PATH rebuilt from the registry at boot** (machine+user, deduped, nonexistent entries dropped). Why: agent-spawned chains strip or backslash-mangle PATH (`C:Windows`); the registry is the only authoritative source. (2026-09-27)
- **Tree is live** — recursive repo watcher + rebuild preserving expansion/selection; drag-drop copies never overwrite (`name (2).ext`). Why: agents write files constantly; a snapshot tree is useless. (2026-09-27)
- **Windows-only, dependency-free renderer, no bundler.** Why: ConPTY/AUMID are the product; readability is a feature. (standing, since 2026-09-26)
- **Knowledge is tracked AS WE GO** — decisions → DECISIONS.md immediately; changes → CHANGELOG; lessons → CLAUDE.md; tasks → TODO.md; prefs/facts → agent memory. "update all docs" = run `/sync-docs`. No button: the 0.6.0 📨 broadcast button was removed in 0.6.6 — a rule, not a UI feature. Why: end-of-session archaeology loses everything the moment it matters. (2026-09-28)
- **Workspaces self-claim their taskbar identity** — at window open: `setAppDetails` (AppID/icon/relaunch/name), auto-create the Start Menu shortcut, purge junk bare `Electron*.lnk`. Why: pinning a running window before its shortcut existed produced "Electron" pins; relying on users to press the launcher's Pin button first failed for 4 of 7 workspaces. (2026-09-28)
- **Default workspace icon = per-name letter mark, never the app logo** — reverses the 0.5.x choice of copying app.ico. Why: a new workspace wearing the VibeSpace logo is indistinguishable from VibeSpace, and taskbar pins freeze whatever icon existed at pin time. (2026-09-28)
- **Logo swaps rewrite taskbar pin .lnk files** (matched by `--workspace=<id>`) + re-call setAppDetails. Why: pins are independent .lnk copies with their own cached icon. (2026-09-28)
- **VibeSpace owns attention toasts inside its terminals** — title `<workspace> · <agent>`, toast unless you're viewing that exact tab; global notify hooks skip their toast when `$VIBESPACE_TERM_STATUS` is set. Why: two toasts per event, and neither named both the repo and the agent. (2026-09-29)
- **"Busy" = the status light, not terminal activity** — a tab with a hook status is busy only while `working` + producing output; others by output only; input never counts. Why: claude's mouse tracking turns mouse movement into terminal input, so activity-based checks cried wolf. (2026-09-29)
- **VibeSpace hooks carry `timeout: 10`** — they block prompt submission; a slow shell start must never hold a message for 30 s. (2026-09-29)
- **Picker resume pins the revived conversation** — right-click `+ Claude` → claude's `--resume` picker; the old session file that starts receiving appends gets pinned. Why: forced blank sessions + untracked `/resume` made restarts resume the wrong conversation. (2026-09-28)
- **Git pane = one pinned tab, two modes (Changes / History), read-only.** Agents own commit/pull/checkout/stash: UI buttons for those would fight agents over the index and swap files under running agents. Why: research of VS Code/GitLens/Desktop/lazygit + multi-agent failure reports (2026-09-29).
- **Every read-only git spawn sets `GIT_OPTIONAL_LOCKS=0` + `GIT_TERMINAL_PROMPT=0`.** Why: `git status` opportunistically takes `.git/index.lock`, so our polling raced agents' commits into "index.lock exists". (2026-09-29)
- **No commit graph yet.** Agent-committed repos are mostly linear, so branch/tag pills and merge dimming carry enough. If we add one, port VS Code's SCM graph layout (MIT, ~90 lines, O(commits×lanes)), not vscode-git-graph (O(n²), non-MIT). (2026-09-29)
- **Git pane stays read-only: no revert/push/discard/fetch buttons.** Valentin: "do as little as possible because Claude Code will be doing the work"; the UI is for reviewing. To undo or push, tell an agent (`revert 6899d7b`, `push`); the commit-id copy in the detail view feeds that. (2026-09-29)
- **Build the Claude-data UI suite: meters, richer tab status, task checklist, agent board, then the rest of RESEARCH-CLAUDE-DATA.md Part C.** Data comes from a statusLine + HTTP hooks injected through the `--settings` file every agent already gets, plus `~/.claude/tasks/`. Transcripts are for history only, since their format is internal and written with a lag. Our statusLine must hand off to the user's own statusLine if one exists. Build on TaskCreate/TaskUpdate, not TodoWrite. Why: Valentin chose all four plus "everything else" (2026-09-29).
- **Claude data feed: the statusLine has no `refreshInterval`, termId maps to its workspace through ptyhost, and the reply is always 200 `{}`.** Reset countdowns are computed in the UI from `resets_at`, so a Git Bash + curl spawn every few seconds per agent buys nothing. One `x-vs-term` header is enough because ptyhost already knows each pty's workspace. Hooks answer `{}` at once and never carry a decision, so the feed can't change claude's behavior. With no port there are no feed entries at all, which is better than red ECONNREFUSED lines in the TUI. The settings generator lives in `claudefeed.addSettings()` (called from `ensureHookSettings`) so smoke and live checks run the exact code. (2026-09-29)
- **Feed detail never overrides the base light, with one exception: a failed turn.** The lock and "?" lights show only while the status files say `waiting`, so lights, toasts and badge keep changing together. StopFailure fires no Stop hook, so the base light would stay amber forever; main toasts and badges it from the feed instead. The instant-red-on-PermissionRequest idea is parked in TODO. (2026-09-29)
- **The `idle_prompt` Notification is not attention.** Only permission_prompt, elicitation_* and agent_needs_input count, plus the AskUserQuestion tool. A finished agent that is just idle is "done", not "needs you". (2026-09-29)
- **Esc is swallowed while a peek card or checklist is open.** Otherwise the same keypress would reach claude in the focused terminal and interrupt a working agent. (2026-09-29)
- **Account limits are shared across VibeSpace processes via `<dataRoot>/limits.json`.** It is written atomically, only when the limits change, and adopted when newer than our copy and under 6 h old. A window past a reset time shows —, not a stale %. Why: limits are account-wide, but each process only hears them from its own agents. (2026-09-29)
- **Tab right-click = options menu, double-click = rename.** Copy session ID / resume command / Agent info need a discoverable home, and a lone rename on right-click hid them. Session items stay visible but disabled until the conversation exists, so users learn they are there. (2026-09-29)
- **The agent board is a read-only overlay inside `#term-hosts`.** It is not a separate view or window: xterms are never disposed or refit on toggle, and the preview pane stays usable. It reads `terms.agents()`/`feedFor()` and never stores its own state, so it can't become a second source of truth. (2026-09-29)
- **Board quick reply only on Done and failed cards.** Permission, question and MCP dialogs are answered in the terminal, because "text + Enter" would select the highlighted option (usually "Yes"). Replies go through `term.paste()` with Enter as a separate write, so claude submits instead of taking the Enter as part of the paste. (2026-09-29)
- **Board summaries get a 60 s heartbeat on top of the "write on change" rule.** Readers hide files older than 2 min, so an idle workspace would otherwise vanish from other boards. (2026-09-29)
- **"Focus another workspace" reuses the launcher's `--workspace=<id>` spawn + single-instance hand-off; the fix was a `!gotLock` guard in `whenReady`.** Without the guard, the losing process still ran a full window/pty boot before quitting. (2026-09-29)
- **Instant attention is an in-memory override in main, never a status-file write** (`main/attention.cjs`). The hooks own the files, and the override goes through the same `applyStatus` path as a file line, so lights, toasts, badge and the busy check stay in lockstep. Two refinements: a PreToolUse `working` line landing late (from a slow Git Bash hook) is ignored while the feed says the dialog is still open, and toasts fire only on a real status change, which gives one toast per waiting episode. (2026-09-29)
- **The feed's `session_id` is the primary termId → session source; the timing heuristic is the fallback.** It is exact because it arrives tagged with our term id, so no birth-time windows are involved. It pins only once the transcript file exists, so a restore never tries to resume an unsaved conversation. `~/.claude/sessions/<pid>.json` is no longer needed. (2026-09-29)
- **Phone control means Claude Code's built-in Remote Control (`claude --rc "<repo> · <tab>"`), not our own phone app or relay.** It runs inside each claude process, so VibeSpace keeps owning the pty, and the Claude phone app already handles transcript, approvals, questions and follow-ups. Server mode (`claude remote-control`) refuses `--settings`, and every third-party tool (Happy, HAPI, Orca) wraps the claude process itself. A DIY Telegram hub is the fallback only if Remote Control proves unreliable. Research: RESEARCH-REMOTE.md. (2026-09-29)
- **Phone control is on for every workspace, with an opt-out per workspace.** While connected, Remote Control stores transcripts on Anthropic's servers, so client/prod repos can switch it off. (2026-09-29)
- **"Away" is Claude Code's `CLAUDE_CLIENT_PRESENCE_FILE`, a marker file that exists while Valentin is at the PC and mutes phone pushes.** VibeSpace owns that file machine-wide: it goes away on lock, on idle, or on the manual toggle, and comes back on unlock or on returning to the PC. Toasts on the PC are unchanged. (2026-09-29)
- **Status words come from HTTP hooks, not Git Bash `echo` hooks** (when the feed runs). Why: command hooks block claude's prompt/tool path, and under load a cold bash start exceeded the 10 s timeout. HTTP hooks are handled in-process and cost no spawn. Status files stay the source of truth, so nothing downstream changed. (2026-09-29)
- **Every claude started in a VibeSpace terminal is tracked, however it was started.** The shell's `claude` wrapper adds our `--settings` and `--remote-control` flags instead of VibeSpace relying on only its own launch line, so a conversation can't slip past the feed and be lost on restart. We chose this over a "resume untracked conversation?" restore toast: Valentin's rule is that an unsaved conversation must not be possible in VibeSpace, not something we recover from afterwards. (2026-09-29)
- **No native dialogs in workspace windows; the in-page `confirmBox()` only.** Why: after a native confirm box closes, Windows Electron stops generating typed characters until the window is re-focused (the "Space stops typing" bug). (2026-09-29)
- **Tab↔conversation changes are always logged (`tabs:` lines) plus an "untracked agent" warning.** Why: a conversation went unrecorded for 12 h, and nothing in the log said so until a restart lost it. (2026-09-29)
- **Toasts only when Valentin is needed; "finished its turn" is off by default.** Per-kind switches live in Preferences and are machine-wide (`notify.json`), not per workspace. Why: with many agents the finished toast fired constantly and buried the ones that need an answer; lights and the taskbar badge still show "done". (2026-09-30)
- **Claude's case-sensitive `/resume` picker (anthropics/claude-code#90588): repair the transcripts, don't build our own picker.** The 41 affected conversations got the drive letter in their `cwd` fields uppercased (originals backed up in `~/.claude/drivecase-backup-2026-10-01`). Why: the issue confirms this as the fix, it touches nothing else, and it costs no VibeSpace code. Our own picker stays an optional TODO for if VS Code-started sessions keep piling up. (2026-10-01)
- **Dropping files onto a terminal pastes their paths, Windows Terminal style** (quoted if they contain spaces, several separated by spaces, sent through `term.paste()`). Dropped text pastes as-is. Why: that's what Claude Code expects from a real terminal: a pasted image path becomes an attachment. Copying the files into the repo stays the tree's job. (2026-09-29)
- **When two sessions need the same files, the one already editing them does the follow-up work.** The ↺ Resume button and the feed re-pin went to vibespace-e2 instead of being built in parallel. Why: shared working tree, own-hunks-only commits; parallel edits to terms.js/index.html would collide. (2026-09-29)
- **A tab rename reaches claude as `/rename`, sent only at a safe moment** (turn done, nothing typed since; otherwise it waits for the next `done`). Why: the Remote Control name is fixed at launch, and `/rename` is the only live way to change it (verified to update the phone). Keystrokes injected mid-prompt or into a dialog would corrupt input, so it waits. (2026-10-01)
- **Tab bar wraps (wrap-reverse), max 3 rows then scroll; no horizontal tab scrolling.** Hidden tabs = forgotten agents; buttons on top when they don't fit beside the tabs, so a narrow (docked-right) pane never squeezes tabs into a column. Why: Valentin asked for multiple rows when agents overflow (2026-10-01).
- **Multiple Claude subscriptions run as token profiles, not separate config dirs.** Each extra Max account is a `claude setup-token` token that VibeSpace sets per tab; they all share one `~/.claude`. When a tab on a Claude account hits its usage limit, it switches automatically: it resumes the same conversation on the next Claude account with headroom. GLM/z.ai stays out of VibeSpace for now. Why: shared `~/.claude` keeps transcripts, tracking, skills and memory intact, and per-account config dirs would split all of them. Valentin found that Claude conversations don't resume well on GLM (they only work as new conversations). Cost: phone control works only on the account logged in with `/login`. (2026-10-01)
- **Every JSON file VibeSpace writes is crash-safe: fsync before rename, last good copy kept as `.bak`, unreadable files restored from it and reported (`json:` log line), never silently defaulted.** State writes are skipped when unchanged. Why: a reboot left recruitica's state.json unreadable; the window silently fell back to defaults and lost its conversation and layout (2026-10-01).
- **On Windows `session-end` (and `before-quit`): one final fsynced save, then state writes are frozen.** Why: at shutdown the ptys can die before main, and the renderer would persist those exits as closed tabs over the good state. (2026-10-01)
- **One ↻ Restart for everything; no separate Claude-update button or `claude update` run.** Claude Code auto-updates on disk before we notice, so the only remaining step is restarting the agents, which the app restart does. Restart confirms only when an agent is busy. (2026-10-01)
- **Tree → File Explorer** — right-click offers Reveal (file/folder selected in its parent, `shell.showItemInFolder`) and Open (folder itself, `shell.openPath`). Why: Valentin asked for both. `fs:openFolder` accepts only folders inside the workspace, because `openPath` on a file launches it. (2026-10-02)
- **Next feature: worktree tabs** (agent in its own git worktree, so parallel agents never touch each other's files). Why: Valentin picked it 2026-10-02 over per-turn diff review / overview window / quick wins. Five sessions colliding in this one tree the same week was the evidence. Design follows a live probe of `claude --worktree` (2.1.287).
- **Worktree tabs: VibeSpace creates and owns the worktree (`git worktree add` → `<repo>\.claude\worktrees\<name>`, branch `vs/<name>`), never `claude -w`.** Why (live probe, claude 2.1.287): `claude -w` MOVES the transcript between project dirs on `/exit` (a hard kill strands it in the worktree's dir), and its clean-exit removal half-fails on Windows (empty folder + branch left). A manual worktree keeps the transcript at munged(<worktree path>) for good, inherits the repo's trust, and gives us our own branch names and cleanup; the tab's shell sits in the worktree too. Close = remove only when nothing is unmerged or uncommitted; merging back is the agent's job (a prompt), never a button. (2026-10-02)
- **xterm uses Unicode 11 widths** (`@xterm/addon-unicode11`, loaded per terminal). Why: the default Unicode 6 table counts emoji as 1 cell while Claude Code and ConPTY count 2, which scrambled Claude's redraws (RESEARCH-TERMINAL-GARBLE.md). (2026-10-02)
- **Typing lag: measure first, no priority guard yet** — `lag:` log lines (key→screen, echo time, CPU %, blocked main/renderer) instead of lowering the priority of agents' test/build processes. Why: Valentin chose "lag log only"; the one observed case was the machine at 100 % CPU from agents' vitest/tsc, not VibeSpace. Revisit the priority guard if the logs keep showing high CPU. (2026-10-02)
- **Parked agents + one + ▾ menu.** Park (tab right-click) STOPS the agent and keeps its conversation, name, worktree and last reply on a shelf. Unpark = resume by id (~5 s; Claude redraws the conversation), and hovering an entry shows the last reply at once. Parked lives in the + ▾ menu's Resume section above "All conversations…" (Claude's picker), plus a 🅿 n chip. The separate ↺ Resume and + Terminal buttons go away; right-click + opens the same menu (Resume was reachable 3 ways). Why: Valentin, 2026-10-03: keep agents for the coming weeks without seeing them all the time, no duplicate buttons, free RAM/MCP servers.
